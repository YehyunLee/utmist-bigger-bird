Goal and where we started

  • Goal: subquadratic attention with quality close to dense on long-context retrieval.
  • Dense R1-Llama-8B retrieves the needle at 128K; cost grows ~n².
  • Eight CCDB R&D rounds (fixed/learned patterns, Top-K, block routing, exp19 Bigger Bird):
    • All-sparse methods: 6/6 at ~65K but 0–1/6 at ~127K, even with 16K routed tokens.
    • Top-K + first 16 layers dense: 6/6 at ~127K, but half the model is still quadratic.
    • Forcing the answer into every sparse layer (oracle) still failed, so routing recall was not the whole story.
  • Today: moved to Modal H100s (about 10× faster per run than the 3g.40GB MIG slices) and rebuilt the R&D loop around one fast diagnostic.

Diagnosis: what does each sparse pattern lose, per layer?

  • One dense forward pass at ~127K. Per layer, compare each candidate pattern's attention output with exact attention.
  • exp19-like routing (local 128 + final-query top-4096): mid-prompt fidelity ~0.85 cosine.
  • Adding attention sinks barely changes it (+0.001), so sinks were not the bug.
  • A wide local window plus per-head routed columns: 0.95+.
  • Errors at mid-prompt tokens compound over 32 layers, so a method can work at 65K and fail at 128K.

Method: Bigger Bird v3

Each query attends to a union of key sets in one Triton sparse FlashAttention kernel (single softmax):

  1. Sinks: first 64 tokens, exact.
  2. Selective local window: previous 16,384 tokens, exact.
  3. Content-routed long links: 512 key columns per head, ranked by the attention of the final 64 prompt queries (the question).
  4. Exact question tail: the final 256 prompt queries attend to every key, O(256·n).

Decode: exact attention over the full KV cache (O(n) per generated token).

Cost per layer, prompt length n:

attention n · (64 + 16384 + 512)
routing 64 · n   tail 256 · n

→ linear in n for fixed budgets (dense: n²/2).

Short prompts (n ≤ window) fall back to exact attention.

What mattered: ablations @~127K (depth 0.5, 6 prompts)

  • Exact question tail is essential: 2/6 without it, 4/6 with 64 queries, 6/6 with 256.
  • Routed budget has a sweet spot: 64 columns gives 0/6, 256–512 gives 6/6, 2K–4K gives 0–4/6. More question-chosen columns shared by every prompt token hurt.
  • Not helpful: max-pooling routes, routing from spread-out queries, restricting routes to late queries.

Subquadratic in practice: fitted scaling exponent

  • Fit of full-model prefill time against prompt tokens, 32K to 127K, log-log:
  • Dense FlashAttention: slope 1.65, heading toward quadratic as attention dominates.
  • Bigger Bird v3: slope 1.01, i.e. linear.
  • Below ~32K the MLPs dominate and the sparse path is no faster.

Attention alone, past the model's context limit

  • One attention layer with Llama-8B shapes on synthetic tensors, including routing and the exact tail.
  • 1M tokens: 18.4 s → 1.04 s (17.8×). 512K: 8.7×. 256K: 4.2×.
  • Each doubling of context: dense costs ~4× more, Bigger Bird ~2× more.
  • Speed only. The model's position limit is 128K, so quality past 128K is untested.

Beyond one needle: harder RULER variants (untuned)

  • At ~32K and ~65K the final config matches or beats dense on every variant: multi-key 11/12 vs 9/12 and multi-value 6/12 vs 3/12 exact at 65K.
  • At ~127K these tasks are hard even for dense (multi-key 4/12, multi-value 0/12). On the essay haystack, sparse trails dense: 11/24 vs 17/24.

Robustness: needle depth @~127K

  • The 4K window fails shallow needles (2/6 at depth 0.1 and 0.25).
  • A 16K local window fixes it: 6/6 at every tested depth.
  • Final config: 6/6, 6/6, 6/6, 6/6, 5/6 at depths 0.1 to 0.9; dense: 5/6, 6/6, 6/6, 5/6, 5/6.
  • Trade-off: about 1.9× instead of 2.65× faster at 127K.

Limits (please read before quoting numbers)

  • Task: repository synthetic NIAH (RULER-style), one model, one seed; not the official RULER suite or general long-context QA.
  • Natural-text haystack at 127K: sparse trails dense (11/24 vs 17/24 exact). Sweeping budgets, window, tail and routing queries did not close the gap.
  • Routing is not prefix-invariant: routes come from the final prompt queries. Attention edges are causal, but earlier positions' routes depend on later text, so this is a full-prompt prefill method, not streaming attention.
  • Tuned on 6 prompts (depths 0.1/0.25/0.5 @127K); 30-prompt confirmation is within-task.
  • Subquadratic = prefill attention work with fixed budgets. MLPs dominate below ~32K; the KV cache still stores every token (memory unchanged); decode is exact O(n) per token.
  • Timings: single H100, BF16, batch 1, warmed (Triton specializes per length), first-forward CUDA-event time.

Next steps

  • Close the 127K natural-text gap (essay haystack 11/24 vs dense 17/24), e.g. per-chunk routing or light sparse-aware fine-tuning.
  • Real-text evals: LongBench-v2 subset, variable tracking; quality past 128K with a longer-context model.
  • Speed: route the 16K window through a native sliding-window FlashAttention kernel; fuse the exact tail; budgets that grow with sqrt(n).
  • Causal variant: per-chunk routing from visible prefix queries, for prefix invariance and cache equivalence.
  • Understand the routed-budget sweet spot: why do too many shared question-routed columns degrade mid-prompt tokens?
  • Reproduce on a second model (e.g. Llama-3.1-8B-Instruct) and more seeds and depths.
